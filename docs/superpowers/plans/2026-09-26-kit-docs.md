# Using the Kit Page Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add `kit.html`, "Using the kit": an embedder's guide to Portrayal's drawings and `@portrayal/kit`. Every recipe runs live beside its own code. The page is reached from a new Docs ▾ menu in the header nav.

**Architecture:**
- Each recipe is one ES module in `site/kit-examples/` exporting `async function run(host)`, which returns a small result object.
- `site/kit-page.js` fetches each module's text to display it, and imports the same module to run it into a result pane.
- The page's import map maps `@portrayal/kit/<module>` to `./vendor/<module>.js`, so examples import exactly as an embedder would.
- `check-contract.py` proves every example import exists in the vendored kit. A `check-browser.py` extra runs every example and checks what it returns.

**Tech Stack:**
- vanilla ES modules and an import map, with no npm and no bundler;
- the vendored kit (`vendor/*.js`) and three.js (`vendor/three/`);
- Python checks (`check-contract.py`, `check-browser.py` with Playwright).

**Spec:** `docs/superpowers/specs/2026-09-26-kit-docs-design.md`

## Global Constraints

- Never edit `vendor/` or `assets/dist/`. They are Portrayal's, refreshed by `refresh-assets.sh`.
- Don't touch `coming-soon/`. This work is main-site only.
- Use American English in all prose (color, center, behavior), including code comments.
- No third-party libraries or CDN scripts. Local code only (Google Fonts stylesheets are already on every page).
- Examples import only via `@portrayal/kit/<module>` or the platform. They never import from `./vendor/…` or `../site/…` directly.
- Each example starts with `const DIST = 'assets/dist/';  // wherever you host the compiled files`.
- The example device is `s9600-72xc` (UfiSpace S9600-72XC), config `base`, view `front`. It is the device the hero uses.
- Colors on the page come from the `--pt-*` tokens (`brand/tokens.css`) and work in both light and dark themes.
- Layout works at phone width: 16px side gutter, no horizontal page scroll.
- The Docs ▾ menu depends on roc-ops/portrayal-site#45 (the navmenu label alignment fix). Task 6 is rebased onto `main` after #45 lands.
- `check-contract.py` must stay green at every commit. Run it before every commit.

## Review Focus

1. **Rerunning an example.** A reader pressing "Run again" twice quickly expects one clean result, not two drawings stacked in the pane. Test: Task 1's browser check clicks "Run again" twice and asserts exactly one `<svg>` in pane 01.
2. **An example that throws.** The reader expects that pane to show the error, and every other example to keep working. Test: Task 1's contract check asserts `kit-page.js` catches around `run()` and writes `data-error`. Task 1's browser check injects a failing example through `?kitfail=1` and asserts its pane shows "failed" while pane 01 still gets its result.
3. **No WebGL.** The reader expects a sentence saying why 3D can't run, not a black box or a console error. Test: Task 4's browser check forces WebGL off (`NO_WEBGL_JS`) and asserts the 3D pane's text mentions WebGL, with no uncaught errors.
4. **Copying an example.** A reader copying code expects the exact module text, not the highlighted HTML. Test: Task 1's browser check reads `copyText` from the Copy handler hook and compares it to a fetch of the file.
5. **The shell example's global CSS.** `createShell` injects a `:root` stylesheet into its document. The reader expects the guide's own colors to be unchanged after the shell example runs. Test: Task 5's browser check compares `getComputedStyle(document.body).backgroundColor` before and after the shell example has run.

## File Structure

- **Create `kit.html`:** the page. It holds the masthead, a sticky table of contents plus the sections, the footer, and the import map. Each recipe is a `<figure class="kit-ex" data-example="NN-name" data-run="view|click|frame">`.
- **Create `site/kit-page.js`:** the runner. It handles fetch → highlight → display, lazy runs, Run again, Copy, and error panes.
- **Create `site/kit-highlight.js`:** a tiny JS highlighter, `highlight(text) → html`.
- **Create `site/kit-frame.html`:** a blank document that runs one example in isolation (`?ex=07-shell`). It exists for the shell example, which styles `:root`.
- **Create `site/kit-examples/`, one module per recipe:**
  - `01-drawing.js`, `02-telemetry.js`, `03-metadata.js`, `04-seat.js`, `05-viewer3d.js`, `06-marks.js`, `07-shell.js`.
- **Modify `site/site.css`:** a `/* ── kit page ── */` block with the layout, TOC, code, result pane and buttons.
- **Modify `check-contract.py`:** the example imports, the listing and the import map (Task 1), and the Docs menu (Task 6).
- **Modify `check-browser.py`:** the `@extra` `check_kit_page`, grown per task, and `kit.html` added to `PAGES` (Task 1).
- **Modify the nine nav pages** (Task 6): `index.html`, `schema.html`, `kit.html`, `explorer.html`, `components.html`, `annotate.html`, `drawio.html`, `exporter.html`, `drawings.html`.

**Ruling (spec §3 says the layout "follows schema.html: … a left table of contents"):** `schema.html` has tabs, not a TOC. `kit.html` borrows the Schema page's masthead, section head and footer, and gets its own sticky TOC. The cost if wrong is only layout.

**Ruling (spec §3 names `setFields` in the 3D recipe and `toPng` / `toGif` in the annotate recipe):** the recipes show `setStates` / `select` / `download` and `apply` / `toSvg` / `encode`. The section leads name the others in one sentence each. A `setFields` call needs a fielded part the S9600 doesn't have, and a PNG or GIF download in a live recipe is noise. The cost if wrong is two lines added to two recipes later.

**Ruling (spec §4 lists the shell example like the others):** `createShell` injects `SHELL_CSS`, which sets `:root` variables, into `document.head`. So the shell example runs in `site/kit-frame.html` inside an `<iframe>`. The code shown is still the file that runs. If wrong, the cost is one iframe.

```js
// A small highlighter for the kit page's recipes: comments, strings, template
// strings, numbers and keywords, nothing else. Local and dependency-free on
// purpose - the page shows plain ES modules, and the coloring only has to help
// the eye, not parse JavaScript.
const KEYWORDS = new Set(('async await break case catch class const continue default do else export ' +
  'false finally for from function if import in instanceof let new null of return switch this throw ' +
  'true try typeof undefined var while').split(' '));

const esc = s => s.replace(/[&<>]/g, c => ({'&': '&amp;', '<': '&lt;', '>': '&gt;'})[c]);

export function highlight(text) {
  const re = /(\/\/[^\n]*|\/\*[\s\S]*?\*\/)|('(?:\\.|[^'\\\n])*'|"(?:\\.|[^"\\\n])*"|`(?:\\.|[^`\\])*`)|\b(\d+(?:\.\d+)?)\b|\b([A-Za-z_$][\w$]*)\b/g;
  let out = '', last = 0, m;
  while ((m = re.exec(text))) {
    out += esc(text.slice(last, m.index));
    const [tok, com, str, num, word] = m;
    if (com) out += `<span class="tk-c">${esc(tok)}</span>`;
    else if (str) out += `<span class="tk-s">${esc(tok)}</span>`;
    else if (num) out += `<span class="tk-n">${esc(tok)}</span>`;
    else if (KEYWORDS.has(word)) out += `<span class="tk-k">${esc(tok)}</span>`;
    else out += esc(tok);
    last = re.lastIndex;
  }
  return out + esc(text.slice(last));
}
```

- [ ] **Step 6: Write `site/kit-page.js`**

```js
// The kit page's runner. Each <figure class="kit-ex" data-example="NN-name">
// shows site/kit-examples/NN-name.js and runs that same module into its pane,
// so what a reader copies is exactly what just ran here.
//
//   data-run="view"   runs when the figure first scrolls into view
//   data-run="click"  runs only when asked (the 3D recipe: it is heavy)
//   data-run="frame"  runs in site/kit-frame.html inside an iframe, for a
//                     recipe that styles :root (createShell does)
//
// A recipe that throws keeps its failure in its own pane (data-error) and the
// rest carry on. Results land on the figure as data-result and on
// window.__kit, which is what check-browser.py reads.
import {highlight} from './kit-highlight.js';

const kit = window.__kit = {results: {}, copyText: {}, run: null};
const gen = {};                                  // name -> run generation

async function source(name) {
  if (kit.copyText[name] == null) {
    const r = await fetch(`site/kit-examples/${name}.js`);
    if (!r.ok) throw new Error(`${name}.js: HTTP ${r.status}`);
    kit.copyText[name] = await r.text();
  }
  return kit.copyText[name];
}

async function runOne(fig) {
  const name = fig.dataset.example;
  const my = gen[name] = (gen[name] || 0) + 1;   // a newer run supersedes this one
  const pane = fig.querySelector('.kit-result');
  delete fig.dataset.result; delete fig.dataset.error;
  pane.replaceChildren();
  pane.classList.add('busy');
  try {
    let result;
    if (fig.dataset.run === 'frame') {
      result = await inFrame(pane, name);
    } else {
      const mod = await import(`./kit-examples/${name}.js`);
      const host = document.createElement('div');
      host.className = 'kit-host';
      pane.append(host);
      result = await mod.run(host);
      if (gen[name] !== my) { host.remove(); return; }   // superseded: leave the newer run's pane alone
    }
    if (gen[name] !== my) return;
    kit.results[name] = result;
    fig.dataset.result = JSON.stringify(result ?? {});
  } catch (err) {
    if (gen[name] !== my) return;
    pane.replaceChildren(Object.assign(document.createElement('p'),
      {className: 'kit-fail', textContent: `This example failed: ${err?.message || err}`}));
    fig.dataset.error = String(err?.message || err);
  } finally {
    if (gen[name] === my) pane.classList.remove('busy');
  }
}

// A recipe that styles :root runs in its own document. The frame imports the
// same module and posts back what run() returned.
function inFrame(pane, name) {
  return new Promise((resolve, reject) => {
    const f = document.createElement('iframe');
    f.className = 'kit-frame';
    f.title = `${name} running on its own page`;
    f.src = `site/kit-frame.html?ex=${encodeURIComponent(name)}`;
    const onMsg = e => {
      if (e.source !== f.contentWindow || e.data?.kitExample !== name) return;
      removeEventListener('message', onMsg);
      e.data.error ? reject(new Error(e.data.error)) : resolve(e.data.result);
    };
    addEventListener('message', onMsg);
    pane.append(f);
  });
}

kit.run = name => runOne(document.querySelector(`figure.kit-ex[data-example="${CSS.escape(name)}"]`));

async function wire(fig) {
  const name = fig.dataset.example;
  const code = fig.querySelector('pre code');
  try {
    code.innerHTML = highlight(await source(name));
  } catch (err) {
    code.textContent = `// could not load ${name}.js: ${err.message}`;
  }
  fig.querySelector('[data-act="run"]').addEventListener('click', () => runOne(fig));
  fig.querySelector('[data-act="copy"]').addEventListener('click', async ev => {
    const text = await source(name);
    try { await navigator.clipboard.writeText(text); ev.target.textContent = 'Copied'; }
    catch { ev.target.textContent = 'Select and copy'; }
    setTimeout(() => { ev.target.textContent = 'Copy'; }, 1500);
  });
}

// ?kitfail=1 adds a recipe that throws, so the checks can prove a failure
// stays in its own pane. Nothing links to it.
if (new URLSearchParams(location.search).get('kitfail') === '1') {
  const first = document.querySelector('figure.kit-ex');
  const fig = first.cloneNode(true);
  fig.dataset.example = 'kitfail';
  fig.dataset.run = 'view';
  first.before(fig);
  fig.querySelector('[data-act="run"]').addEventListener('click', () => runOne(fig));
  kit.copyText.kitfail = '';
  (async () => {
    const pane = fig.querySelector('.kit-result');
    pane.replaceChildren();
    fig.querySelector('pre code').textContent = '// a recipe that throws';
    try { throw new Error('a deliberate failure'); }
    catch (err) {
      pane.append(Object.assign(document.createElement('p'),
        {className: 'kit-fail', textContent: `This example failed: ${err.message}`}));
      fig.dataset.error = err.message;
    }
  })();
}

const io = new IntersectionObserver(entries => {
  for (const e of entries) {
    if (!e.isIntersecting) continue;
    io.unobserve(e.target);
    runOne(e.target);
  }
}, {rootMargin: '200px'});

for (const fig of document.querySelectorAll('figure.kit-ex')) {
  if (fig.dataset.example === 'kitfail') continue;
  wire(fig);
  if (fig.dataset.run === 'view' || fig.dataset.run === 'frame') io.observe(fig);
}

// The table of contents marks the section in view.
const toc = [...document.querySelectorAll('.kit-toc a[href^="#"]')];
const spy = new IntersectionObserver(entries => {
  for (const e of entries) {
    if (!e.isIntersecting) continue;
    for (const a of toc) a.toggleAttribute('aria-current', a.getAttribute('href') === `#${e.target.id}`);
  }
}, {rootMargin: '-40% 0px -55% 0px'});
for (const a of toc) {
  const s = document.getElementById(a.getAttribute('href').slice(1));
  if (s) spy.observe(s);
}
```

```js
// The drawing is the API. A compiled face is an ordinary SVG: every part carries
// a stable data-path, and a lamp takes its color from a state class the drawing
// already styles. No kit needed - fetch, insert, query.
const DIST = 'assets/dist/';  // wherever you host the compiled files

export async function run(host) {
  const text = await fetch(`${DIST}s9600-72xc.base.front.svg`).then(r => r.text());
  host.insertAdjacentHTML('beforeend', text);
  const svg = host.querySelector('svg');

  // Find a port by its path, and light its lamp. `state-on` is one of the
  // states this lamp declares (data-states="off on"); the drawing paints it.
  const port = svg.querySelector('[data-path="port-12"]');
  svg.querySelector('[data-path="led-port-12/lamp"]').classList.add('state-on');

  // Any part tells you what it is when clicked: its data-path.
  const out = document.createElement('output');
  out.textContent = 'Click a port.';
  host.append(out);
  svg.addEventListener('click', ev => {
    const part = ev.target.closest('[data-path]');
    if (part) out.textContent = part.dataset.path;
  });

  return {lit: [port.dataset.path]};
}
```

```js
// Seat a real part in a cage: an SR optic in port-4, with its two LC plugs.
// The keys are drawing paths - the cage, then the optic's own LC bores - and
// the values are component references. applyFaceOverrides draws each part's
// own artwork into the face; encodeSwaps turns the same map into a URL slot.
import {applyFaceOverrides, encodeSwaps} from '@portrayal/kit/swap';
import {jdist} from '@portrayal/kit/dist';

const DIST = 'assets/dist/';  // wherever you host the compiled files

const seats = {
  'port-4': 'generic/sfp-lc@1',
  'port-4-occupant/tx': 'generic/lc-plug@2',
  'port-4-occupant/rx': 'generic/lc-plug@2',
};

export async function run(host) {
  const text = await fetch(`${DIST}s9600-72xc.base.front.svg`).then(r => r.text());
  host.insertAdjacentHTML('beforeend', text);
  const svg = host.querySelector('svg');          // in the document: the kit measures

  const idx = await jdist(`${DIST}s9600-72xc.configs.json`);
  const {components} = await jdist(`${DIST}components.json`);
  const byRef = ref => components.find(c => `${c.ns}/${c.name}@${c.major.slice(1)}` === ref.split(':')[0]);
  const loadSkin = async ref => {
    const c = byRef(ref);
    if (!c) return null;
    const skin = c.skins?.includes('default') ? 'default' : c.skins?.[0];
    const r = await fetch(`${DIST}components/${c.ns}--${c.name}--${c.major}--${skin}.svg`);
    return r.ok ? {comp: c, text: await r.text()} : null;
  };

  const res = await applyFaceOverrides(svg, {bays: idx.bays?.front || [], cages: idx.cages?.front || []},
                                       seats, loadSkin, byRef);
  const out = document.createElement('output');
  out.textContent = `?swaps=${encodeSwaps(seats)}`;
  host.append(out);
  return {seated: res.applied, refused: [...res.refused, ...res.failed], url: encodeSwaps(seats)};
}
```

```js
// Annotate: a marks document names parts by selector and says what to do to
// each - ring it in a color, set a lamp state, label it. apply() previews it on
// the live drawing; toSvg() writes a standalone SVG with the rings and a legend
// as plain geometry (it opens in Word); encode() fits the document in a URL.
import {apply, toSvg, encode} from '@portrayal/kit/marks';

const DIST = 'assets/dist/';  // wherever you host the compiled files

const doc = {
  device: 's9600-72xc', config: 'base', view: 'front', legend: true,
  marks: [
    {select: '[data-path="port-12"]', color: '#2bb3c8', label: 'uplink to spine-a'},
    {select: '[data-path="led-port-12/lamp"]', state: 'on'},
    {select: '[data-path="port-67"]', color: '#e0574f', label: 'CRC errors rising'},
  ],
};

export async function run(host) {
  const text = await fetch(`${DIST}s9600-72xc.base.front.svg`).then(r => r.text());
  host.insertAdjacentHTML('beforeend', text);
  const svg = host.querySelector('svg');           // in the document: rings are measured

  apply(svg, doc);                                 // preview on the page
  const standalone = toSvg(svg, doc);              // a file you can save or send
  const share = encode(doc);                       // ?m=<this> reopens it in Annotate

  const out = document.createElement('output');
  out.textContent = `annotate.html#m=${share.slice(0, 48)}…`;
  host.append(out);
  return {marks: doc.marks.length, svgBytes: standalone.length, share};
}
```
